# 架构现状

更新日期：2026-07-27

## 当前定位

项目是一个 Python 多智能体协作编程原型：

1. Tester 根据任务生成测试用例。
2. Critic 审查测试用例，Tester 根据反馈修订。
3. Coder 生成目标 Python 代码。
4. Verifier 执行代码和测试。
5. 验证失败后，错误反馈进入下一轮 Coder 修订。

```text
用户任务 -> Tester -> Critic -> 测试套件
         -> Coder -> AST 检查 -> Docker 执行
         -> 成功 / 携带反馈重试
```

## 当前事实

- Docker 执行已禁网，生成的 runner 以只读卷挂载，并有宿主机超时。
- Docker 不可用时仍会自动回退到宿主机 `exec()`，这是待修复的最高优先级风险。
- 主要代码集中在 `demo.py`，数据结构主要使用松散的 `dict`。
- 尚无自动化测试、基准数据集、持久化 Trace 和成本统计。
- 当前目录还不是 Git 仓库。
